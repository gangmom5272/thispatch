# 패치 추출 문맥·근거 검증

## 이번 변경의 범위

`fix/ai-patch-extraction-context`에서 기존 Qwen 추출 경로를 개선한다. 기존 화면 수정 브랜치와 보관본은 사용자 요청으로 삭제했다. 게임별 이름 사전, Spark 규칙, 임베딩 입력, 운영 데이터는 변경하지 않는다.

- 본문이 같아도 제목·소제목이 다르면 별도 입력으로 처리한다.
- 제목을 실제 요청에 전달하고 개별 변경점의 근거 구절을 요구한다.
- 대상·속성·수치·조건의 원문 연결을 검사하고, 잘못된 한 항목만 조용히 버리는 부분 성공을 허용하지 않는다.
- 재시도 후에도 속성 이름만 원문과 다르면 그 이름은 null로 보존한다. 수치·대상·조건·근거 문장은 계속 엄격히 검사한다.
- `source_sentence`를 기존 `evidence_quote`에 저장한다. HDFS Parquet 스키마는 유지한다.
- 모델 판본·입력 해시를 구분해 재개하고, 적용할 결과가 현재 청크와 같은 입력인지 쓰기 전에 확인한다.

## 확인한 문제와 해결 범위

| 문제 | 이전 동작 | 이번 처리 |
|---|---|---|
| 같은 본문, 다른 소제목 | 본문 해시로 결과 공유 | 제목·문맥·본문·판본 모두 일치할 때 공유 |
| 긴 청크의 다른 수치를 가져옴 | 대상 이름 포함 여부로 valid 가능 | 해당 변경의 인용 구절 안에서 속성·수치 검사 |
| 응답 일부 누락·중복 ID | dict 변환으로 누락/덮어쓰기 가능 | 요청 ID별 정확히 한 결과 확인 후 항목별 재시도 |
| 일반어·일부 토큰만 일치 | 일반 대상어 또는 60% 토큰 일치면 valid | 실제 원문 구절 일치 요구 |
| 과거 응답을 새 판본으로 반영 | 적용 코드의 MODEL_TAG로 재표기 가능 | 현재 판본 결과만 적용 |
| 오래된 소제목의 결과 적용 | 현재 입력과 대조하지 않음 | 현재 청크와 원본 응답의 입력 해시 확인 |

## 실제 데이터에 대한 근거

2026-09-23 확보한 검색 허용 변경점 57,378개에서 소유격 뒤 무기·스킬 관련 문자열이 462개 변경점·149패치·95게임에 등장했다. 문자열 탐색 결과이며 정확도나 신규 복구 수치가 아니다. War Thunder의 `ship’s bow`, Blade Symphony의 봇 무기 변경 불가 수정, Rain World의 이동 능력 복구 문장을 회귀 입력으로 사용했다.

`tests/fixtures/patch_context_examples.json`은 저장 원문과 출처를 보존한다. 참고 라벨은 개발자가 제안한 값이며 독립 검수된 정답셋이 아니다. 기본 테스트는 이 라벨의 원문 연결을 확인할 뿐, Qwen이 실제로 해당 라벨을 생성했다고 주장하지 않는다.

## 의미 정확도 평가 절차

1. 규칙을 통과한 사례뿐 아니라 `unknown/partial`, 짧은 항목, 긴 복합 항목, 소제목에 대상이 있는 항목, UI·버그·성능·밸런스 변경을 포함한다. 기존 검색 허용 표본만 사용하면 누락을 측정할 수 없다.
2. 게임별 표본 수에 상한을 두고, 같은 게임의 패치가 개발용·평가용 양쪽에 섞이지 않게 나눈다. 동일 본문/재게시도 분리한다. 구체적인 게임 목록·규모는 실제 실행 전에 확정한다.
3. 대상 이름/종류, 속성, 행동, 전후 값, 조건, 근거 구절을 사람이 검수한다. 모호한 대상은 강제로 이름이나 종류를 채우지 않는다. 두 검수자가 다른 라벨은 원문을 보고 합의하거나 모호 사례로 별도 집계한다.
4. 기존 규칙, 이전 Qwen 판본, 새 판본을 같은 고정 입력에 실행한다. 모델·프롬프트·입력 해시를 기록한다.
5. 유형별 정밀도/재현율, 변경 사실 전체의 연결 정확도, 누락률, unknown 비율, 근거 거부율, 시간·요청 수를 함께 비교한다. valid 증가만으로 개선이라고 판단하지 않는다.
6. 검증용 게임에서 얻은 결과와 새로운 게임의 결과를 따로 보고한다. 배포 허용 기준은 검수 결과를 보고 합의하며 임의의 숫자를 성공 기준으로 선언하지 않는다.

## 한계

- 문자열 근거가 일치해도 `bow`의 의미나 대상 분류가 틀릴 수 있다. 의미 정확도는 실제 모델과 검수 라벨로 평가해야 한다.
- 모델이 긴 근거 구절을 반환하면 그 안의 여러 속성을 잘못 연결할 가능성이 남는다. 프롬프트는 단일 사실을 요구하지만 검증기는 자연어 의미를 증명하지 않는다.
- 기존 청크에서 이미 사라진 소제목·목록 경계는 복원하지 않는다. 임베딩 입력/청크 구성을 바꾸는 작업은 별도 호환성 검토가 필요하다.
- 기존 청크당 최대 8개 변경점 출력 한도와 원문 조건 누락에 따른 미탐지 문제는 남는다.
- 근거 검사를 강화하면 정상적인 의역·번역도 거부될 수 있다. 새 프롬프트는 원어 인용을 요구하며 실제 거부율은 live 평가 대상이다.
- 구판 응답 JSONL은 신판 적용기가 새 판본으로 취급하지 않는다. 모든 워커와 프롬프트·적용기를 함께 갱신해야 한다.

운영 Qwen 백필·HDFS 업로드·Spark 적재·DB 수정은 이번 작업에서 하지 않는다.

### 원본 응답 수신 후 수정 (`service-facts-4`, `plan-grounded-2`)

전달받은 코드 해시 3개가 전달본과 모두 일치했다. 원본 응답 6개를 `tests/fixtures/qwen_observed_responses.json`에 보존했다.

1. 기획안의 두 시도 모두 `내구도`를 `내구성`으로 바꿨다. 두 번째 시도에서 속성 이름만 근거와 다르면 null로 비운다. 수치 30%와 원문·제외 조건은 보존하며, 동의어 사전으로 이름을 자동 복구하지 않는다.
2. Blade Symphony의 `ability to change weapon`도 조립된 표현이다. 항목별 재시도에서 속성 이름만 원문과 다를 경우 비운다. 원문과 조건은 그대로 검사한다.
3. **속성 오류 외에 게임 간 응답 혼합도 있었다.** Blade Symphony ID에는 War Thunder의 RN Italia 변경점이 추가됐고, War Thunder ID에는 Rain World의 Artificer 변경점이 들어갔다. 속성만 null로 바꿔도 이 결과들은 source_sentence 검사에서 거부된다. 묶음 실패 시 기존 개별 재시도 경로를 유지하며, 개별 재시도에서도 다른 게임의 문장이 남으면 저장하지 않는다.
4. Rain World의 자기 ID에 속한 실제 응답은 원문 검증에 통과한다. `Artificer/player/fix`였으며, 개발자가 제안한 `Artificer/unknown/change`와 일치하지 않는다는 이유만으로 오류라 단정할 수 없다. 실모델 테스트를 초안 라벨과의 완전 일치 대신 명시된 변경의 보존, 버그 수정/능력 복구를 신규 추가로 바꾸지 않기, 배의 선수를 무기로 분류하지 않기 기준으로 바꿨다. 이는 정밀도·재현율 평가가 아니다.
5. 잘못된 values를 null로 비우는 제안은 채택하지 않았다. 틀린 수치를 빼고 성공 처리하면 수치가 없는 원문과 잘못 추출한 응답을 구별하기 어려워진다.

실제 수신 응답을 HTTP 대체 응답으로 재생하는 회귀 테스트를 포함해 로컬 55개 중 50개 통과, 실모델 5개 미실행이다. 기존 혼합 응답을 개별 재시도에도 반환하는 모의 조건에서는 Rain World 1건만 저장되고 다른 게임의 문장 2건은 계속 거부됨을 확인했다. 새 모델 실행에서 개별 요청이 정확한 답을 줄지는 별도 검증해야 한다.

속성이 없으면 AI가 만드는 화면 재진술에는 원문을 사용한다. **다만 백엔드 CaseSearchService.toPlanChange는 검색 문장을 슬롯 값으로 다시 만들므로 원문 표시만으로 검색 정보 손실까지 해결되지는 않는다.** 속성 미확인 기획안은 검색 전 사용자가 속성을 보완해야 하며, 자동 검색까지 원문을 보존하려면 별도 계약·전달 경로 개선이 필요하다. 이번 수정은 그 백엔드/프론트 경로를 바꾸지 않았으며 운영에 배포하지 않았다.

### v2 실모델 결과와 따옴표 수정 (`service-facts-5`)

전달된 v2 코드 해시 4개가 현재 전달본과 모두 일치했다. 기획안 테스트 4개는 모두 통과했고, 배치 테스트 하나 안에서 Blade Symphony·War Thunder의 subTest 2개가 실패했다. unittest의 `tests=5, failures=2`는 이 경우 최상위 테스트 3개만 성공했다는 뜻이 아니다.

이번 배치 응답은 게임별 ID가 맞았으며 혼합은 재현되지 않았다. 묶음 호출은 Blade Symphony의 조립된 속성 때문에 재시도로 넘어갔다. 개별 재시도에서 `bot’s/ship’s`가 `bot's/ship's`로 바뀌어 근거 대조가 실패했다. 묶음의 War Thunder 조건에도 `on the ship's bow`가 있어 문장뿐 아니라 조건 대조에도 같은 문제가 있었다.

- 배치 `source_excerpt`에서 작은따옴표 세 문자(`'‘’`)끼리, 큰따옴표 세 문자(`"“”`)끼리만 동등하게 매칭한다. 원문 문자열을 변경하거나 Unicode 전체 정규화를 적용하지 않는다. 정규식이 찾은 원문 구간을 반환해 저장 시 글자와 부호를 복원한다.
- 작은따옴표와 큰따옴표 사이 교체, 따옴표 삭제, prime(`′`), 대시·마이너스·범위 기호는 동등하게 보지 않는다. 수치/단어 검증은 유지한다.
- 기획안 검증기와 프롬프트 문장은 이번에 변경하지 않았다. 배치 검증 동작과 재사용 판본을 구분하기 위해 `service-facts-5`로 올렸다.
- `qwen_observed_v2_responses.json`에 실제 응답 9개를 보존했다. 실제 테스트 시나리오 5개를 저장된 응답으로 모두 재생해 통과했고, 세 게임 모두 개별 재시도 후 원문에 맞는 결과가 저장됐다. 판본 변경에 따른 요청 ID 해시만 대응시켰으며 모델이 반환한 사실·인용·분류는 수정하지 않았다.
- 로컬 전체 59개 중 54개 통과, 별도 GPU 호출 5개는 건너뜀. 위 재생 테스트는 이 54개 안의 회귀 테스트이며 새로운 모델 추론 실행으로 보고하지 않는다. v1의 다른 게임 근거 혼입, 잘못된 수치·대상·조건 거부 회귀도 유지했다.

확인된 v2 실패의 원인 수정은 저장 응답으로 검증했다. 새로운 모델 출력의 안정성, 넓은 게임 표본의 정확도, 운영 재적재는 이 검증 범위에 포함되지 않는다.
