# Git 컨벤션

브랜치 생성, 커밋, 이슈 및 PR(MR) 작성 시 적용한다.

## 브랜치 전략

### 기본 브랜치

| 브랜치  | 설명                                                  |
| ------- | ----------------------------------------------------- |
| main    | 운영 배포용 브랜치. 항상 배포 가능한 상태를 유지한다. |
| develop | 개발 통합 브랜치. 완성된 기능을 병합하고 테스트한다.  |

### 개발 브랜치

```text
{타입}/#{지라이슈키}/{간략이슈내용}
```

예시: `feat/#S15P11A503-38/user-register`

- 각 기능, 버그 수정, 리팩토링 등 작업마다 개별 브랜치를 생성한다.
- 타입은 소문자를 사용하고, 간략 이슈 내용은 소문자 영단어와 하이픈(-)으로 작성한다. Jira 이슈 키는 원래 표기를 유지한다.
- 작업 브랜치에서 개발 및 Push 후 PR을 통해 `develop`으로 병합하고, 병합된 작업 브랜치를 삭제한다.
- `hotfix`는 긴급 수정으로 바로 `develop`에 Push해야 하는 경우에 사용한다.

| 타입 (소문자) | 의미                                            |
| ------------- | ----------------------------------------------- |
| feat          | 새로운 기능 구현                                |
| chore         | 부수적인 코드 수정 및 기타 변경사항             |
| docs          | 문서 추가 및 수정, 삭제                         |
| fix           | 버그, 오류사항 수정                             |
| test          | 테스트 코드 추가 및 수정, 삭제                  |
| refactor      | 코드 리팩토링                                   |
| build         | CI/CD, 빌드 관련                                |
| hotfix        | 긴급 수정으로 바로 develop에 Push해야 하는 경우 |

## 커밋 컨벤션

전달된 형식:

```text
{타입}: [{지라이슈키}] [{역할}] {커밋 메시지}
```

전달된 예시:

```text
feat: [S15P11A503-38] 회원가입 및 로그인 구현
```

| 타입 (첫 글자 대문자) | 의미                                |
| --------------------- | ----------------------------------- |
| Feat                  | 새로운 기능 구현                    |
| Chore                 | 부수적인 코드 수정 및 기타 변경사항 |
| Docs                  | 문서 추가 및 수정, 삭제             |
| Fix                   | 버그, 오류사항 수정                 |
| Test                  | 테스트 코드 추가 및 수정, 삭제      |
| Refactor              | 코드 리팩토링                       |
| Build                 | CI/CD, 빌드 관련                    |

### 확인 필요 (TBD)

- 타입 표는 첫 글자 대문자(`Feat`)를 명시하지만 예시는 소문자(`feat`)이다. 최종 대소문자 기준은 확인이 필요하다.
- 형식에는 `[{역할}]`이 있지만 예시에는 없다. 역할의 필수 여부와 허용 값은 확인이 필요하다.
- 위 차이는 임의로 확정하지 않고, 실제 커밋 작성 전에 확인한다.

## 이슈 템플릿

제목:

```text
[FEAT] 진행할 작업으로 이슈 제목 작성
```

본문:

```markdown
## 작업 설명

<!-- 진행할 작업을 설명해주세요 -->

## ✅ To do

<!-- 필요한 투두를 적어주세요 -->

- [ ]
- [ ]
```

## Pull Request (Merge Request) 템플릿

제목:

```text
FEAT(#{issue number}): 진행한 작업으로 PR 제목 작성
```

본문:

```markdown
## 작업 내용

-

## 주요 변경 사항

-

## 영향 범위

- [ ] Backend
- [ ] Frontend
- [ ] Database
- [ ] Spring Batch
- [ ] Hadoop / HDFS
- [ ] Spark / YARN
- [ ] AI Server
- [ ] Infra / Docker
- [ ] 문서

## 테스트

- [ ] 빌드 / 실행 확인
- [ ] 변경 기능 정상 동작 확인
- [ ] 기존 기능 영향 확인

### 테스트 방법 및 결과

-

## ⚠️ 추가 확인 사항

<!-- DB 스키마 변경, 환경변수 추가, 인프라 설정 변경 등 공유가 필요한 경우 작성 -->

- 없음

## 관련 이슈

Closes #

## 리뷰 요청 사항

-
```
