# Playwright 브라우저 테스트

실제 백엔드 없이 API 응답을 제어하며 사용자 흐름을 검증한다. 브라우저에서 라우팅, 폼, TanStack Query, API 클라이언트와 화면을 실행하지만 백엔드·DB 연동을 검증한 결과는 아니다.

## 실행

```powershell
pnpm test:e2e
pnpm test:e2e:ui
pnpm test:e2e e2e/plans.spec.ts
pnpm test:e2e --grep "내 게임"
pnpm exec tsc -p e2e/tsconfig.json --noEmit
```

Playwright 설정이 `http://localhost:5174`에 전용 Vite 서버를 시작하고 종료한다. 해당 포트는 비워 두어야 한다. 기존 개발 서버를 재사용하지 않는다. 서버는 `VITE_ENABLE_MOCKS=false`, `VITE_API_BASE_URL=/api`로 실행하고 브라우저의 Service Worker도 차단해 MSW와 응답 가로채기가 충돌하지 않도록 한다.

프로젝트 의존성과 Playwright Chromium이 설치되어 있어야 한다. 브라우저 실행 파일이 없다면 `pnpm exec playwright install chromium`으로 준비한다.

## 데이터와 작성 기준

- `fixtures/data.ts`는 고정된 계정·게임·기획안 응답을 제공한다.
- `fixtures/test.ts`는 테스트별로 독립적인 계정·등록 게임·API 핸들러를 준비한다. 테스트 간 실행 순서나 외부 계정에 의존하지 않는다.
- 로그인 자체를 검증하지 않는 테스트는 `storageState`로 시작한다. 저장된 실제 인증 파일이나 비밀정보는 사용하지 않는다.
- 테스트별 `api.set("METHOD /path", handler)`로 응답을 교체할 수 있다. 정의하지 않은 API 요청은 실패로 보고하여 누락된 응답을 숨기지 않는다.
- 지연 응답은 Promise를 명시적으로 해제한다. 고정 시간 대기, 강제 클릭, DOM 구조·CSS 기반 선택자를 사용하지 않는다.
- 캐시된 화면으로 돌아오는 동작에서는 반드시 새 HTTP 요청이 발생한다고 가정하지 않는다. 화면과 URL의 결과를 검증한다.
- 기획안 초안은 같은 브라우저 문서 안에서 게임별로 복원된다. 새로고침 후 초안 보존은 현재 기능 범위가 아니다.
- 실패는 테스트 선택자·응답 오류인지 실제 제품 결함인지 구분한다. 제품 결함을 숨기기 위해 `skip`, `fixme`, `fail`로 정상 처리하거나 검증을 줄이지 않는다.
